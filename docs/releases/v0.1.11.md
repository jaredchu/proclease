ProcLease v0.1.11 is an experimental prerelease. It packages the
lifecycle, terminal-safety and release-hardening changes from an independent
review of v0.1.10, together with the matching
[ProcLease skill guidance](https://github.com/jaredchu/proclease/blob/v0.1.11/skills/proclease/SKILL.md).

## Lifecycle

- **Jobs from an earlier boot.** The keeper now saves opaque digests of the
  machine and of its boot (Linux: machine ID with host name, and the kernel
  boot ID; macOS: hardware UUID and boot session UUID). A record proven to come
  from an earlier boot of the same machine has no process left: it is shown
  finished, with `finished_at_ms` still `null`, and history collection removes
  it under the normal 24-hour and 100-job limits. Records from another machine
  sharing the state directory, records without a complete identity and records
  written by v0.1.10 or earlier prove nothing and are kept as before.
- **Absent supervision.** A `starting` or `running` record whose saved keeper,
  guardian process group and command are all observed absent in the same PID
  context is shown `interrupted` instead of `unknown`. A missing saved PID, or
  a live or uncertain observation, keeps it `unknown`. The display is never
  written back and does not make the record collectable.
- **Faster stops.** After TERM, KILL follows as soon as no other live process
  remains in the group and captured output has reached end-of-file, instead of
  always waiting the whole grace. A group that ignores TERM, and any incomplete
  or uncertain process observation, still gets the whole grace. Launch-metadata
  grace is capped at 10 seconds in every supervisor.
- **Foreground signals.** SIGINT, SIGTERM or SIGHUP to `run --foreground` now
  records a requested stop (`stopped`, reason `requested`), like
  `proclease stop`. Killing the invocation is still recorded as `interrupted`
  with reason `supervision_lost`. Agents that treated `interrupted` as the
  normal result of an interrupt should accept `stopped`.

## Output and internals

- Terminal output also escapes Unicode bidirectional formatting characters,
  which can visually reorder untrusted log text. Emoji joiners are kept.
- Resource sampling reads process groups once per sample.
- File locks use the Rust standard library instead of the unmaintained `fs2`
  crate. The minimum Rust version stays 1.89.
- Records may contain the new optional `machine_context` and `boot_context`
  fields. JSON `schema_version` stays 1.

## Packages and checks

The release workflow checks native macOS ARM64 and Intel, and Linux ARM64
and x64 using glibc. It runs the Rust suite on each target, builds and
extracts the archive, checks that the packaged job expires, and exercises
installer failures for bad archives or checksums. Workflow actions are pinned
to commit SHAs. These checks cover the packaged CLI and installer. Native
agent behavior remains scoped to the
[compatibility evidence](https://github.com/jaredchu/proclease/blob/main/docs/agent-compatibility.md).

This is the first release whose four archives and `install.sh` carry signed
GitHub build provenance. Verify a download with:

```sh
gh attestation verify FILE --repo jaredchu/proclease \
  --signer-workflow jaredchu/proclease/.github/workflows/release.yml
```

The archives include the binary, portable skill, README, and license.
The macOS minimum is 15.0. The existing experimental signing limitations
are described in the [v0.1.9 notes](https://github.com/jaredchu/proclease/blob/v0.1.9/docs/releases/v0.1.9.md).

## Installation

Review the release's `install.sh`, then run:

```sh
sh install.sh --skills both
proclease --version
```

The expected version is `proclease 0.1.11`. The installer checks the
download checksum and can install the skill for both supported agents.
Omit `--skills both` for a CLI-only installation. Registry publication is
separate.
