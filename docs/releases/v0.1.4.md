ProcLease v0.1.4 is an experimental compatibility prerelease. It fixes source
installation with Rust/Cargo 1.89 on affected macOS hosts. Command-line behavior,
state layout, JSON schema, runtime source and dependencies are unchanged.

## Cargo installation fix

Release stripping previously applied to build-time procedural-macro libraries.
On the macOS verification host, Rust 1.89 could not load the stripped
`clap_derive` library (E0463). The release profile now leaves host build units
unstripped while the installed CLI keeps symbol stripping, release optimization
and thin LTO. No environment override is needed for the fixed package.

A new CI job packages the source and installs it with Rust 1.89 defaults on
macOS and Linux, alongside stable formatting, Clippy, all three unit plus
thirty-one integration tests and optimized builds. The previous manifest failed
as a local control; the fixed package passed. See
[verification](https://github.com/jaredchu/proclease/blob/v0.1.4/docs/verification.md#cargo-189-build-time-stripping-fix-2026-11-07)
for evidence and the limits of the diagnosed cause.

The immutable crates.io 0.1.3 package still has its documented caveat. Install
the corrected version with Rust 1.89 or newer:

```sh
cargo install proclease --version 0.1.4 --locked
proclease --version
```

Cargo installs the CLI; the portable skill is installed separately. ProcLease is
binary-only, so docs.rs provides a crate overview, README and source rather than
a library API.

## Prebuilt installation

Download this release's `install.sh`, review it, then run:

```sh
sh install.sh --skills both
proclease --version
```

The installer selects a native archive, verifies its SHA-256 checksum and
installs without sudo or Rust. Existing unrelated skill folders are preserved.
Omit `--skills both` for CLI-only installation. Manual archive downloads include
the CLI, portable skill, README and MIT license; verify them against `SHA256SUMS`.
Website download links and the installer are pinned to this version together.

## Compatibility and limits

The release workflow builds and tests native macOS Apple Silicon and macOS 15
Intel binaries and Ubuntu 22.04 ARM64/x64 (glibc) binaries. Both macOS targets
use a macOS 15.0 deployment minimum; older macOS is not separately runtime-tested.
Windows and Linux musl/Alpine binaries are not provided.

macOS binaries are not Developer ID signed or notarized. Publisher signing and
notarization are planned before a stable macOS release, and remain deferred for
this experimental prerelease. SHA-256 checksums verify downloaded bytes and do
not replace an authenticated publisher signature.

ProcLease manages only services launched through it. It is a supervisor, not a
sandbox: descendants that create a new process group can escape cleanup. Use
native storage for state inside VMs. Reading status, logs or resources never
renews a lease. See the README for support limits.
