ProcLease v0.1.10 is an experimental prerelease candidate. It packages
updated [ProcLease skill guidance](https://github.com/jaredchu/proclease/blob/v0.1.10/skills/proclease/SKILL.md)
with the lifecycle implementation from v0.1.9.

## Skill guidance

- When handing a managed service between Codex and Claude Code, carry
  the job ID, registry selection, task and owner labels, service directory,
  and expiry. Verify the job in that registry before acting.
- Use JSON output at launch to capture the job identity. For cleanup of
  a fixed set, preview the matches, then stop the authorized jobs by exact
  ID and confirm their terminal state. Bulk stop selects the matching set
  again when applied.
- Preserve the task's authorization boundary during handoff. A declared
  owner or task label identifies a candidate job and supplies no authority.

## Packages and checks

The release workflow checks native macOS ARM64 and Intel, and Linux ARM64
and x64 using glibc. It runs the Rust suite on each target, builds and
extracts the archive, checks that the packaged job expires, and exercises
installer failures for bad archives or checksums. These checks cover the
packaged CLI and installer. Native agent behavior remains scoped to the
[compatibility evidence](https://github.com/jaredchu/proclease/blob/main/docs/agent-compatibility.md).

The archives include the binary, portable skill, README, and license.
The macOS minimum is 15.0. The existing experimental signing limitations
are described in the [v0.1.9 notes](https://github.com/jaredchu/proclease/blob/v0.1.9/docs/releases/v0.1.9.md).

## Installation

After publication, review the release's `install.sh` and then run:

```sh
sh install.sh --skills both
proclease --version
```

The expected version is `proclease 0.1.10`. The installer checks the
download checksum and can install the skill for both supported agents.
Omit `--skills both` for a CLI-only installation. Registry publication is
separate. The live site stays on v0.1.9 during candidate validation.
